# CLAUDE.md

## Project

Multi-vendor order processing engine (home assignment): lowest-price vendor selection, splitting an order into vendor sub-orders, queued notifications, React UI.

## Commands

```bash
composer dev            # everything: serve + queue worker + vite + pail logs (php artisan dev)
composer test           # config:clear + pint --test + phpstan + artisan test  (the full gate)
php artisan test        # fast loop
php artisan test --filter=OrderSplitTest          # single class
php artisan test --filter='it splits by vendor'   # single test
php artisan test tests/Feature/OrderTest.php      # single file
composer lint           # pint --parallel (fix)
composer types:check    # phpstan (larastan level 7)
npm run lint            # eslint --fix
npm run format          # prettier on resources/
npm run types:check     # tsc --noEmit
```

Annotate generics (`Collection<int, Order>`, `HasMany<OrderItem, $this>`) or PHPStan fails.
The declaring model of a relation is `$this`, never the class name — `TDeclaringModel` is
not covariant, so `HasMany<OrderItem, Order>` is rejected inside `Order` itself.

### Test environment

`phpunit.xml` sets only `APP_ENV=testing`; **everything else comes from `.env.testing`**, which points at a real MySQL database `multivendor_order_engine_testing` (not SQLite, not in-memory). Create that schema once; `RefreshDatabase` migrates it. Never re-add `<env>` DB overrides to `phpunit.xml` — they would win over `.env.testing`.

`.env.testing` is gitignored — copy `.env.testing.example`, run `php artisan key:generate --env=testing`, fill in the MySQL credentials.

```bash
php artisan migrate --env=testing     # apply a new migration to the test schema
```

## Architecture

**Two delivery layers over one domain core.**

- **Inertia (`routes/web.php`)** — controllers return `Inertia::render('page-name', [...])`. Pages are auto-resolved by `@inertiajs/vite` from `resources/js/pages/*.tsx` (lowercase-kebab filenames). `HandleInertiaRequests::share()` puts `name` and `auth.user` on every page.
- **JSON API (`routes/api.php`)** — registered in `bootstrap/app.php`, prefixed `/api`, stateless (no session/CSRF), `api` middleware group. `withExceptions` already renders JSON for `api/*` and any `expectsJson()` request. Responses go through `App\Http\Resources\*`; controllers live in `App\Http\Controllers\Api\`.

Neither layer holds business logic — both call the same actions/services in `app/`. Duplicating order logic between a web controller and an API controller is the mistake to avoid.

**Wayfinder generates typed route helpers.** `resources/js/routes/`, `actions/`, `wayfinder/` are generated by the vite plugin from PHP routes and are gitignored — never edit or commit them; import route/action helpers from there in TSX instead of hardcoding URLs. Adding a route means the dev server (or a build) must run before the TS import exists.

**Queues are database-backed and asynchronous.** Notifications and async order work are pushed to the `jobs` table and executed by a worker — `composer dev` runs one, otherwise `php artisan queue:work`. Nothing runs inline, so assert dispatch with `Queue::fake()` / `Notification::fake()` / `Bus::assertDispatched` rather than on a job's side effect.

**Global defaults live in `AppServiceProvider::configureDefaults()`** — `CarbonImmutable` for all dates, destructive DB commands prohibited in production, strong password rules in production only.

## Conventions

Laravel-idiomatic, modular, OOP. Skinny controllers.

- **Collections over loops.** `Collection::map/filter/groupBy/sum/sortBy/partition/each` instead of `foreach`/`array_*`. Vendor selection and order splitting are naturally `groupBy` + `sortBy` + `first` pipelines — write them that way.
- **One responsibility per class.** Domain logic goes in `app/Actions` or `app/Services` (single public `handle()`/`execute()`), not in controllers or models. Models hold relations, casts, scopes.
- **Form Requests** for validation, **API/Inertia Resources or typed arrays** for shaping props, **Events + queued Listeners/Notifications** for side effects (vendor notification is a listener, not inline controller code).
- **Enums** (`app/Enums`) for statuses — never string literals.
- **snake_case everywhere for data names** — variables, model properties/attributes, array keys, DB columns, JSON/props keys, TS interface fields. Classes stay `StudlyCase`, methods stay `camelCase`. A payload key keeps the same spelling from the DB column through the Resource to the TSX prop — no camelCase conversion at the boundary.
- Eager-load relations (`with()`); no N+1 in listing endpoints. Wrap multi-write flows (order + sub-orders + items) in `DB::transaction`.
- `declare(strict_types=1)` is not used by the starter — match surrounding files. Constructor property promotion + typed properties throughout.
- Frontend: React 19 function components, TypeScript types in `resources/js/types/`, Tailwind v4 utilities, `cn()` from `resources/js/lib/utils.ts` for class merging.

**No comments.** Make the code read without them; if it can't, rename things until it does.
